# v0.3 重构：扁平化任务模型（砍段 / 砍子任务）

> **状态**：设计稿，待 v0.3 实施
> **作者**：Mavis（2026-08-12 plan-mode 会话）
> **决策日期**：2026-08-12
> **影响版本**：v0.3.0（alpha → 内部测试）

---

## 1. 背景

v0.1 / v0.2 的数据模型是三层：

```
Plan（计划，容器）
  └── TimeSegment（时间段，挂在 plan 下）
        └── Task（任务，挂在 segment 下）
              └── TaskCompletion（任务在某天的实例）
```

跑了一年发现：

- **"段"对用户太抽象**——实际使用时，用户说"晨练 6-8 点"就够，不需要"晨练段 + 跑步任务 + 拉伸任务"这种嵌套
- **三层 CRUD 心智成本高**——建一个 5 分钟活动要操作 3 张表
- **空计划点 + 出来的是"新建段"**，用户期望是"新建任务"——产品和用户直觉错位

**v0.3 决定砍成两层**：

```
Plan（计划，容器）
  └── Task（任务，自带起止时间 + 重复规则）
        └── TaskCompletion（任务在某天的实例）
```

砍掉段实体，子任务也不要（先按简单来）。

## 3. 核心算法：链式碰撞延期

### 3.1 规则（用户原话 + 我的精确化）

**用户原话**：

> 如果任务延期后，和当天内按时间顺序的下一个任务的时间有重合，就把下一个任务延期，然后下一个任务也是按照这种规则。一直到当天的最后一个任务。自动延期是跨计划的，而且只延期当天的，不会影响后来的。

**精确化后的规则**：

1. **触发**：某个任务状态变为 `IN_PROGRESS` 且当前时间 `now` 超过它的 `plannedEnd`（即 `overrun = now - plannedEnd > 0`）
2. **范围**：`scheduledDate == today` 的所有 `TaskCompletion` 实例（明天的不动）
3. **排序**：按 `computedStartAt` 升序——`computedStartAt` = `actualStart ?: plannedStart`（已被之前的延期推过的按推后值算）
4. **算法**：从超时的 IN_PROGRESS 任务位置往后扫：
   ```
   对每个相邻对 (prev, cur)：
     若 prev.isLocked == true → 链断，cur 不被推（cur 之后的任务也不被推）
     否则若 prev.computedEndAt > cur.computedStartAt：
       cur.plannedStart += delta
       cur.plannedEnd   += delta
       cur.affectedTasks += prev.taskId
   ```
5. **跨计划**：所有 plan 的任务混排，按绝对时间排，不分组
6. **只改当天**：`scheduledDate != today` 的实例一律不动

### 3.2 伪代码

```kotlin
class CascadeDelayCalculator @Inject constructor() {

    /**
     * @return 调整后的 completions 新列表（输入不被修改）
     */
    operator fun invoke(
        completions: List<TaskCompletion>,
        tasks: List<Task>,
        today: LocalDate,
        now: LocalDateTime,
    ): List<TaskCompletion> {
        val taskMap = tasks.associateBy { it.id }

        val todayInstances = completions
            .filter { it.scheduledDate == today }
            .sortedBy { it.computedStartAt() }

        if (todayInstances.isEmpty()) return completions

        val result = todayInstances.toMutableList()
        for (i in 0 until result.lastIndex) {
            val prev = result[i]
            val prevTask = taskMap[prev.taskId] ?: continue
            val cur = result[i + 1]
            val curTask = taskMap[cur.taskId] ?: continue

            // locked 钉死，链到这就停
            if (prevTask.isLocked) break

            // 已完成/跳过的不动它们（也不应让它们被推）
            if (cur.status == TaskStatus.COMPLETED || cur.status == TaskStatus.SKIPPED) continue
            if (prev.status == TaskStatus.COMPLETED || prev.status == TaskStatus.SKIPPED) continue

            val prevEnd = prev.computedEndAt()
            val curStart = cur.computedStartAt()

            if (prevEnd.isAfter(curStart)) {
                val delta = Duration.between(curStart, prevEnd)
                result[i + 1] = cur.copy(
                    plannedStart = cur.plannedStart.plus(delta),
                    plannedEnd   = cur.plannedEnd.plus(delta),
                    affectedTasks = cur.affectedTasks + prev.taskId,
                )
            }
        }

        // 未参与当天的原样返回
        val unchanged = completions.filter { it.scheduledDate != today }
        return unchanged + result
    }

    private fun TaskCompletion.computedStartAt(): LocalDateTime =
        actualStart ?: plannedStart

    private fun TaskCompletion.computedEndAt(): LocalDateTime =
        actualEnd ?: plannedEnd
}
```

### 3.3 isLocked 语义（用户已确认）

- `isLocked=true`：**钉死**，链式延期到此停止
  - 这个任务的 `plannedStart/End` 永不被改
  - 排在它**之后**的任务**不**被它推走（链断了）
  - 排在它**之前**的任务推过来撞上它时，**撞到就停**——不会"穿过去"
- `isLocked=false`（默认）：参与链式碰撞

### 3.4 与 v0.2 算法的对比

| 维度 | v0.2 `AutoExtendCalculator` | v0.3 `CascadeDelayCalculator` |
|---|---|---|
| 触发 | 累计 currentOffset（多个 IN_PROGRESS 累加） | 单点超时链式碰撞 |
| 粒度 | 段内任务链 | **跨计划**全天任务链 |
| 已完成/跳过 | 不影响 | 不影响（显式 continue） |
| locked | 不被推 | 不被推 + 链断 |
| 范围 | 当天 | 当天 |
| `affectedTasks` | 当前所有 affectors | 仅上游直接碰撞的 prev taskId |

**测试覆盖**：v0.2 单测 4 个 case，v0.3 需要至少 6 个 case：
1. 单个超时推下一个
2. 链式 3 个（A 超时 → 推 B → B 也超时 → 推 C）
3. locked 钉死，链断
4. 已完成的不影响链
5. 跨 plan 任务混排
6. 不影响明天（`scheduledDate != today` 不参与）

手工验收（commit 4 之后开始）：

1. **冷启动空数据库**：建计划「健身」→ 进计划详情 → FAB 加任务「晨练 06:00-08:00 / 工作日」→ 列表出现

3. **链式碰撞**：手动把系统时间拨到 06:45 还在晨练 → 看下一个任务（如果有）是否被推到 08:00 后
4. **locked 钉死**：建任务 A 06:00-07:00 + B 06:30-07:00 (locked) + C 07:00-08:00 → A 推到 07:00 → 撞 B → B 不动 → C 不动（链断）
5. **跨 plan 混排**：建 plan A 任务 06-07 + plan B 任务 06:30-07 → 时间线按绝对时间混排显示
