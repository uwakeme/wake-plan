# Wake Plan — v0.4~v0.6 功能计划

| 项目 | 内容 |
|---|---|
| 关联 | `docs/plan/00-roadmap.md` §11 v0.4 候选 / `docs/INTERNAL_TEST.md` 已知问题 |
| 决策日期 | 2026-09-11 头脑风暴会话拍板 |
| 节奏 | 分四个阶段推进；阶段一+二 = v0.4 内测收口，阶段三 = v0.5，阶段四 = v0.6 |

## 0. 决策背景

v0.3.1 内测后盘点，剩余工作分四类：**必需补漏**（承诺了没兑现/有数据隐患的半成品）、**体验优化**（用户每天感知得到的）、**路线图存量**（roadmap §11 排了没动的）、**大特性**（番茄钟）。优先级：正确性 > 日常体验 > 存量 > 大特性。

番茄钟形态已拍板：**绑任务的专注页**（从 Today 选任务进全屏计时，结束一键打卡，专注时长进统计，需要新表 + schema v4）。

## 1. 阶段一：必需补漏（v0.4.0 主体）

| # | 事项 | 现状 | 做法 |
|---|---|---|---|
| 1 | 备份导入包 Room 事务 | `BackupImporter.applyV1` wipe+insert 两步裸跑，注释自认「v0.2 再加事务」未加；中途失败可能清库后没写回 | 注入 `WakePlanDatabase`，`applyV1` 包进 `db.withTransaction { }`；补「insert 中途失败 → 数据保持导入前状态」测试 |
| 2 | BootReceiver 重启重排闹钟 | Manifest 声明了 `RECEIVE_BOOT_COMPLETED` 但没有 receiver；重启后 starting alarm 全丢 | 新建 `notification/BootReceiver.kt`（@AndroidEntryPoint，goAsync + 协程）：`BOOT_COMPLETED` / `TIME_SET` / `TIMEZONE_CHANGED` → 查当天 PENDING completion → `ScheduleManager` → `StartingAlarmScheduler.scheduleAll()`（幂等）；调度判定抽纯函数单测 |
| 3 | TaskEditor 补 isLocked | 新建任务设不了锁，只有编辑已有任务时（PlanDetail）能设 | TaskEditorScreen 加开关，接线 TaskEditorViewModel 已有字段 |
| 4 | 模板应用补全 | 砍段时删了 `TemplateTaskSpec`，`specFor()` 恒 null，`createPlanFromTemplate` 只建空 plan | `BuiltInTemplateSpec` 加回 `tasks: List<TemplateTaskSpec>`（title/startMinutes/endMinutes/repeatRule/customDays/isLocked/note）；实现 `specFor()` 给 3 个内置模板配任务；`createPlanFromTemplate` 建 plan 后同事务复制任务（保 orderInPlan）；`enrichWithSpec` 返回带任务模板，TemplateDetailScreen 预览自然显示 |
| 5 | 归档接线 | `PlanEntity.archived` schema v2 已有，domain/UI 全没接 | domain `Plan` 加 `archived` + mapper；PlanList 卡片菜单「归档/取消归档」+「已归档」折叠区；归档计划从 Today 聚合 / 级联延期 / 统计排除（走 isActive 同路过滤） |
| 6 | 通知渠道去占位 | `task_completed` / `plan_recap` 只有渠道 + 设置开关，无发通知代码 | task_completed：打卡完成发低优先级通知（`NotificationContentBuilder` 扩展）；plan_recap：本期隐藏开关（阶段三做每日回顾） |

## 2. 阶段二：体验优化（v0.4 收口项）

| # | 事项 | 现状 | 做法 |
|---|---|---|---|
| 7 | Widget 实时刷新 | 只在系统 update / 开 App 时刷，打卡后桌面组件滞后 | Hilt singleton 在 app scope collect 当日数据 Flow，变化即用 `TodayWidgetProvider` 现有 RemoteViews 构建推送 |
| 8 | 快速录入 | 建计划 3-4 步（INTERNAL_TEST 已知问题） | Today FAB → 底部弹层快速建任务（标题 + 起止时间 + 计划选择器，默认最近计划），保存后走 `TaskCompletionInstantiator` 铺当天实例；不动 schema |
| 9 | 冲突可视化 | `ConflictDetector` 算法有，PRD US-09 承诺的内联提示未完整呈现 | Today 时间线 + PlanDetail 列表内联标注（重叠色条/图标 + 简短文案），不弹 modal |

**阶段一+二完成 = v0.4 内测收口**：更新 `docs/INTERNAL_TEST.md` changelog、release notes、roadmap §12，打 tag。

## 5. 验收口径

- 每个 behavior 同步加测试（JUnit5 + MockK，参考同包 `*Test.kt`）；每次提交前单测全绿 + `:app:lintDebug`。
- 阶段一/二各事项 commit 后 push main；v0.4 收口时 `assembleDebug` + emulator 冒烟。
- 阶段四动 schema 前单独 commit（entity + DAO + migration + 测试），再上功能。
